# GYMRECORD

手機優先的本機健身紀錄 APP。以 Push、Pull、Leg、Upper、Lower 五種分日菜單開始，逐組記錄重量與次數。

## 開始使用

需要 Node.js。於此資料夾執行：

```powershell
npm install
npm run dev
```

在同一台電腦開啟 `http://127.0.0.1:5173/gymrecord/`。正式版本可用 `npm run build` 建立於 `dist/`。

## GitHub Pages 與 Android PWA

正式測試網址：[https://shaochun04.github.io/gymrecord/](https://shaochun04.github.io/gymrecord/)。`main` 更新後，GitHub Actions 會依序執行 `npm ci`、`npm test`、`npm run build`，通過後把 `dist/` 部署至 GitHub Pages；執行狀態可在儲存庫的 Actions 頁查看。正式網站使用 `/gymrecord/` 路徑與 HTTPS。

在 Android 手機的 Chrome 開啟上述網址，等待網頁載入後，從右上角選單選擇「安裝應用程式」或「加到主畫面」，依畫面確認，再從主畫面圖示開啟。選單文字會隨 Chrome 版本不同。若尚未出現安裝選項，先確認網址是 HTTPS、GitHub Actions 部署已完成，再重新載入。

**資料只存在裝置本機。** GitHub Pages 只提供 APP 檔案，不接收訓練紀錄；每台裝置、每個瀏覽器網站來源各有自己的 IndexedDB，沒有帳號或自動同步。原本在 `localhost` 的資料不會因開啟 GitHub Pages 而搬到手機；請先在原處匯出 JSON，並在手機版設定中匯入。清除 Chrome 網站資料、移除 PWA 或換手機前，請先匯出備份並確認檔案可讀。備份仍為 v3，舊 v1／v2 備份可匯入。

## 目前功能

- 可編輯、新增、刪除訓練菜單；從全域動作庫選擇動作，設定菜單專屬的重量、次數、組數與備註。
- 可複製菜單，保留全域動作引用與菜單設定，並為新菜單和每個動作欄位產生新的 ID。
- 動作庫可建立、搜尋、依器材或肌群篩選、編輯肌群、封存與合併動作。封存不會刪除既有菜單與歷史。
- 從菜單開始訓練，帶入上次完成的重量與次數。
- 逐組直接輸入或用加減按鈕調整重量、次數，標記暖身組、完成組、增加或刪除組別。
- 訓練中自動儲存；重新開啟後可繼續未完成訓練。
- 訓練中可用上移／下移調整當次動作順序；結束前若有未完成正式組或動作，會先顯示確認。
- 訓練時查看每個動作上次完成的正式組重量、次數與 RIR；完成正式組後可選填 RIR 0～4+。
- 根據上次正式組與目標次數區間顯示簡單的漸進超負荷建議，不會自動修改重量或次數。
- 上次顯示與新訓練預填依全域動作 ID 跨菜單採用最近一次已完成的正式組；不同器材或變化分開追蹤。
- 在日曆查看有訓練的日期，並檢視當天的重量與組數、各動作最高重量趨勢。
- 進步頁可查看同一全域動作的逐組歷史、重量 PR、各重量的次數 PR 與 Epley 估算 1RM PR；肌群頁顯示週一開始的每週主要肌群有效組數、訓練天數和未分類組數。
- 已完成的訓練可在詳情中修正各組重量、次數、RIR、完成狀態與暖身／正式組；PR、紀錄訓練量和肌群統計會從修正後的紀錄重算。完成摘要會提示本次新重量或同重量次數 PR，進步頁另顯示單一動作的紀錄訓練量趨勢。
- 可切換公斤／磅；完成一組後自動倒數休息，可加減 15 秒或跳過。
- 訓練中顯示經過時間與動作備註；完成後顯示時間、組數及正式組訓練量摘要。
- 匯出／匯入 JSON 完整備份，以及匯出 CSV 訓練紀錄。

所有訓練內容儲存在目前瀏覽器的 IndexedDB，沒有帳號與遠端資料庫。清除瀏覽器網站資料或換裝置前，請從設定匯出備份。PWA 的離線快取會在正式建置後啟用。

## Android APK 方向

保留目前的 React 與 Vite 介面，之後以 Capacitor 建立 Android 專案，再透過 Android Studio 建置 APK。手機版仍以本機紀錄為主。瀏覽器與 APK 的儲存空間彼此獨立，換到手機時需先在原裝置匯出 JSON 備份，再於 APK 匯入。封裝前須確認 Android 端的備份匯出／匯入流程與本機資料保存方式。

## 資料結構

菜單中的每個動作欄位引用一筆全域 `ExerciseDefinition`，並保存該菜單專屬的預設重量、次數、目標區間、組數、休息時間與備註。開始訓練時會保存當時名稱、器材與變化的快照，之後修改動作定義不會更動舊紀錄的顯示文字；歷史、PR 與上次紀錄則依全域 ID 分組。肌群分類保存在動作定義，修正分類後會重新計算過去各週組數。重量在資料庫中以公斤儲存。進步建議、PR 與肌群統計由歷史紀錄即時計算，不另存資料。

## 資料存取架構

畫面透過 `src/data/workoutRepository.ts` 的 `WorkoutRepository` 讀寫訓練資料，透過獨立的 `WorkoutChangeSource` 接收資料變更。網頁版沿用 `gymrecord` IndexedDB，Dexie v3 upgrade 會掃描舊菜單、已完成與進行中的訓練，建立全域動作並保留原有 ID、RIR 與目標區間。遷移只自動合併標準化後完全相同的名稱與器材，不猜測變化或肌群；僅存在舊歷史中的動作會封存。菜單、動作定義與 session 可分開查詢；`readAll()` 只供一致性的完整備份使用。還原與動作合併都在單一 transaction 中完成，失敗時回滾。同一時間最多一筆進行中的訓練。

備份輸出 v3 JSON，仍可匯入 v1 與 v2。`src/data/backupSchema.ts` 依舊版欄位驗證、逐版遷移，再用 v3 schema 驗證所有動作引用；全部完成後才呼叫 `replaceAll()`。舊菜單的預設 reps 會轉成相同的目標上下限；舊訓練的目標區間與 RIR 留空，不推測過去的訓練目標。CSV 保留原欄位及 RIR、目標次數欄位。

Phase 4 仍使用 IndexedDB 與備份 v3；已完成紀錄的修正只更新原 Session 的組別資料，不改 ID、時間、全域動作引用或名稱快照。

之後做 Android APK 時，可在啟動處換成 SQLite adapter，維持同一組資料模型和 `WorkoutRepository` 介面。這只共用資料操作方式，不會讓瀏覽器與手機資料自動同步；離線轉移仍使用 JSON 匯出與匯入。手機版還需處理原生檔案選取與分享，才能完成備份流程。

執行 `npm run build` 檢查型別與建置，`npm test` 執行備份、資料庫及訓練計算測試。

## 手機操作驗證

Phase 1.1 已用隔離的 Chrome 行動版視窗檢查 320、360、390、412、430 px 寬度，包含 6 組訓練、長動作名稱與備註、休息控制、kg/lb 顯示，以及訓練中重新整理後恢復。另以縮短視窗檢查輸入框聚焦捲動，並模擬背景停用超過休息時間後返回。Phase 2 再以獨立本機測試頁檢查加入 RIR 後的 360、390、412 px 訓練畫面：選擇器六個按鈕都留在卡片內，頁面沒有橫向溢出；重新整理後繼續訓練，已選的 RIR 4+ 仍保留。

Phase 3 以獨立本機測試頁檢查 360、390、412 px 的菜單編輯動作選擇、動作庫與肌群進度；以長動作名稱、長器材名稱、變化及主要／次要肌群多選測試，未發現橫向溢出。

Phase 4 以獨立本機測試頁檢查 360、390、412 px 的菜單複製、訓練中動作排序、歷史編輯及進步頁。歷史編輯使用固定底部儲存按鈕，避免多組紀錄需要捲到底才能儲存；以上畫面未發現橫向溢出。另確認修正後的重量與 RIR 會在重新開啟歷史詳情時保留。自動測試涵蓋舊備份遷移、v3 往返及歷史修正後的匯出／清空／匯入。

**仍需實機驗證：** 以下項目尚未在實際 Android 手機執行，桌面行動版視窗無法代替。開始長期使用前，建議先匯出 JSON 備份，再依序記錄結果：

- [ ] 從 Android Chrome 安裝 PWA，關閉後由主畫面重開
- [ ] 開始訓練；關閉重開後 active Session 能恢復
- [ ] 系統數字鍵盤與重量／次數 ± 按鈕
- [ ] 完成組與 RIR 輸入
- [ ] 背景切換與鎖屏後，休息倒數仍按實際時間恢復
- [ ] 長時間訓練與當次動作排序
- [ ] 結束 Session，確認未完成組提醒及摘要
- [ ] 編輯已完成的歷史紀錄
- [ ] 檢查 PR、紀錄訓練量與肌群統計更新
- [ ] 匯出 JSON 備份並確認手機可找到檔案
- [ ] 匯入 JSON 備份並確認紀錄一致
